# 覆盖策略

## 按功能点类型选择覆盖维度

不同类型的功能点需要不同的测试覆盖策略，避免"三板斧"式的机械覆盖。

### 覆盖类型定义

| 覆盖类型 | 说明 | 示例 |
|---------|------|------|
| 正向验证 | 正常输入，期望正确结果 | 输入有效金额，订单创建成功 |
| 异常验证 | 非法输入或错误条件 | 输入负数金额，提示错误 |
| 边界验证 | 边界值、临界条件 | 金额=0, 金额=最大值 |
| 等价类 | 相同处理逻辑的输入分组 | 1-100 为普通订单, 101+ 为大额订单 |
| 权限验证 | 不同角色的操作权限 | 管理员可删除，普通用户不可 |
| 并发验证 | 多用户/多请求同时操作 | 两人同时修改同一订单 |
| 幂等验证 | 重复操作产生一致结果 | 重复点击提交不会创建多个订单 |
| 兼容性验证 | 不同环境/版本/配置 | 新旧版本数据兼容 |
| 可观测性 | 日志、审计、数据完整性 | 操作后日志是否正确记录 |
| 集成验证 | 跨模块/跨系统交互 | 订单创建后库存是否正确扣减 |

### FP 类型与覆盖策略矩阵

| FP 类型 | 必选 | 推荐 | 可选 |
|--------|------|------|------|
| calculation (计算) | 正向 | 边界、等价类 | 可观测性 |
| constraint (约束) | 正向 | 异常(违反约束) | 边界 |
| workflow (流程) | 正向 | 分支、幂等/并发 | 边界 |
| api_behavior (接口) | 正向 | 参数/响应/状态码、并发/幂等 | 可观测性 |
| data_record (数据) | 正向 | 可观测性、边界(精度/长度) | 并发(乐观锁) |
| config (配置) | 正向 | 兼容性(配置变更) | 并发 |
| ui_interaction (交互) | 正向 | 异常(输入校验)、边界 | 兼容性 |

### 覆盖选择逻辑

```
对每个 FP:
1. 确定 FP 类型
2. 查矩阵 → 获取必选/推荐/可选覆盖类型
3. 必选：一定生成
4. 推荐：默认生成，除非用户明确排除
5. 可选：仅当需求涉及时生成

特殊规则:
- 如果需求涉及权限 → 所有 FP 加权限验证
- 如果需求涉及并发 → workflow/api 类 FP 加并发验证
- 如果需求涉及多端 → 所有 UI 类 FP 加兼容性验证
```

## 用例合并原则

生成用例时，同类测试应合并，避免用例膨胀：

| 合并条件 | 示例 |
|---------|------|
| 同一字段 + 多个边界值 | 排序：-1 / 0 / 极大值 → 合为一条「排序字段边界值校验」 |
| 同一字段 + 多个异常值 | 排序：非数字 / 负数 / 空 → 合为一条「排序字段异常值校验」 |
| 同一字段 + 多种格式限制 | 图片：gif / 超1M / 恰好1M → 合为一条「图片格式与大小校验」 |
| 同一组件 + 类似 UI 操作 | 弹窗：取消 / × 关闭 → 合为一条 |

**不合并的情况：**
- 不同字段的测试（名称校验 ≠ 图片校验）
- 不同验证目的（正向 ≠ 异常 ≠ 边界）
- 不同业务场景

## 关联层覆盖

除了原子 FP 的用例，还需覆盖关联层：

| 关联类型 | 生成用例类型 | 目标 |
|---------|-------------|------|
| data_flows (数据流) | 集成用例 | 验证 FP 之间数据流转一致性 |
| invariants (不变量) | 校验用例 | 验证跨 FP 全局约束成立 |
| lifecycle (生命周期) | E2E 用例 | 验证完整业务路径正确性 |
