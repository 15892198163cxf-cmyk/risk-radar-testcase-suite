# 详细模式额外要求（标准模式不需要）

## 1. 前后端校验分离
每个校验规则写两条用例：
```
用例A（前端校验）：在页面上操作，验证前端是否拦截
用例B（接口校验）：绕过前端，直接调接口，验证后端是否拦截
```
覆盖场景：
- 必填校验：前端空值提交 + 接口空参数
- 格式校验：前端非法输入 + 接口非法参数
- 长度校验：前端超长输入 + 接口超长参数
- 唯一性校验：前端重复提交 + 接口重复参数
- 权限校验：前端按钮隐藏 + 接口无权限调用
- 文件校验：前端文件类型/大小限制 + 接口直接上传恶意文件

## 2. 接口级测试
所有增删改操作必须补充：
- 参数缺失测试（必填参数不传）
- 参数类型错误（数字字段传字符串）
- 参数越界（超过最大值/最小值）
- 未授权调用（无token/过期token）
- 重复提交（相同参数连续调用）

## 3. 状态流转全覆盖
操作×状态矩阵**每个格子**都要写用例（标准模式只覆盖主路径）：
```
        | 状态A | 状态B | 状态C |
操作1   | ✅    | ✅    | ✅    |
操作2   | ✅    | ✅    | ✅    |
操作3   | ✅    | ✅    | ✅    |
```

## 4. 提示文案逐条验证
PRD 中每个红色提示、toast 提示、确认弹窗文案，都要有一条用例验证：
- 文案内容是否与 PRD 一致
- 显示位置是否正确（输入框下方/页面顶部/弹窗等）
- 触发条件是否正确

## 5. 数据一致性验证
每个写入操作后验证：
- 列表页数据刷新是否正确
- 详情页数据是否与提交一致
- 关联页面数据是否同步更新
- 数据库数据是否正确（如有条件）

## 6. 粒度基准学习（详细模式强制前置步骤）
生成前**必须**先读取关联模块的往期用例，学习实际写法粒度：
1. 抽样 3-5 条往期用例，看它按哪些维度拆条
2. 回答 3 个问题：
   - 往期同类用例的平均粒度是什么？
   - 往期按哪些维度拆条？（版本/OS/语言/设备类型/操作方向？）
   - 当前模式要求什么粒度？
3. 按往期粒度展开，不能凭感觉"概括一下"

详细模式拆条维度清单（逐个检查）：
- [ ] 客户端版本：V5 / V6完整版 / V6精简版 → 各写一条
- [ ] 操作系统：Windows / MAC → 各写一条
- [ ] 语言版本：中文 / 英文 → 各写一条
- [ ] 设备类型：每种专区设备 → 各写一条
- [ ] 操作方向：先选A再选B / 先选B再选A → 各写一条
- [ ] 前后端：前端操作 / 绕过前端调接口 → 各写一条

⚠️ 错误做法：凭感觉写"联动测一下就行"，一个场景 1 条概括
⚠️ 正确做法：先学往期粒度，再按拆条清单展开

## 7. 原子用例不等于单步骤

- “一条用例只验证一个核心规则”约束的是**验证目的**，不是步骤数量。
- 进入页面、定位对象、输入数据、提交操作、刷新或重新进入等动作必须按实际执行顺序编号。
- 只有纯查看、纯点击或单次接口调用等确实只有一个动作的场景，才允许只有一个编号步骤。
- 禁止把“输入并保存”“删除后刷新查看”“打开页面并直接调用接口”等多个动作压成一步。
- `atomicity_exemption` 只能解释为什么一个验证目的需要联动多个状态或表面，不能豁免步骤可执行性。

详细模式的机械生成门槛：当用例集不少于 20 条，若至少 95% 都只有一个编号步骤，且至少 3 条单步中包含多个可执行动作，则自审必须失败，禁止导出。

## 8. 步骤与预期动作闭环

- 预期包含“接口返回/接口拒绝/状态码”时，步骤必须明确实际调用的接口、请求数据和身份条件。
- 同一权限规则的“前端按钮隐藏”和“直接调用接口被拒”必须拆成两条详细用例。
- 不得只在预期结果中新增步骤里没有执行的操作或校验表面。
