# 反馈学习 Prompt 模板 v1

## 用途
当用户对生成的用例提出反馈时，按此模板提取学习内容。

## 反馈分类

### 类型 A: 规则缺失
- **特征**: 用户指出某个业务逻辑/约束被遗漏
- **示例**: "你漏了紫鸟盒子离线时的处理逻辑"
- **动作**: 询问是否存为新规则 → 创建规则文件

### 类型 B: 覆盖遗漏
- **特征**: 用户指出某个测试场景没覆盖到
- **示例**: "并发场景没考虑到"
- **动作**: 更新 learned-patterns.yaml 中的覆盖策略补丁

### 类型 C: 格式问题
- **特征**: 用户对输出格式不满意
- **示例**: "步骤描述太笼统了"
- **动作**: 更新 output_format.md 或 testcase_generation.md

### 类型 D: 理解偏差
- **特征**: 用户指出需求理解有误
- **示例**: "不是这个意思，应该是..."
- **动作**: 修正当前用例，记录到 feedback-log.md

## 反馈处理流程

```
收到反馈
  ↓
判断类型（A/B/C/D）
  ↓
执行修改（修正当前用例）
  ↓
询问用户："这个调整是通用的吗？以后类似需求都这样？"
  ├─ 是 → 提取规则/模式 → 存入知识库
  └─ 否 → 仅记录到 feedback-log.md
```

## 反馈记录格式

```markdown
### FB-NNN (YYYY-MM-DD)
- **需求**: [需求简述]
- **反馈类型**: A/B/C/D
- **原始问题**: [出了什么问题]
- **用户调整**: [用户改成了什么]
- **提取规则**: [通用规则] 或 "无（仅限本次）"
- **已存为规则**: rule-NNN 或 "否"
```
