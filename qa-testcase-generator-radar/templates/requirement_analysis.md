# 需求分析 Prompt 模板 v1

## 用途
当接收到需求文档/描述后，按此模板进行需求分析。

## 分析流程

### 第一步：通读理解
- 完整阅读需求
- 识别核心业务目标
- 标记关键术语和概念

### 第二步：信号扫描
按 references/methodology.md 的 18 类信号逐一扫描：
- 重点关注：条件信号、状态信号、异常信号（最容易遗漏）
- 图片输入：关注 UI 元素、按钮状态、数据展示

### 第三步：功能点提取
对每个发现的信号，提取功能点：
- 确保满足原子性（单一行为 + 可独立验证 + 明确预期）
- 分类 FP 类型（参考 references/fp_types.md）
- 记录 test_hints（测试方向提示）

### 第四步：关联分析
- 数据流：FP-A 的输出 → FP-B 的输入
- 不变量：多个 FP 共同维护的全局约束
- 生命周期：从创建到结束的完整路径

### 第五步：知识库关联
- 查询知识库是否有匹配规则
- 如有 → 补充规则中的约束和场景到分析结果
- 如无 → 标记为纯新需求

### 输出格式

```markdown
## 需求理解
[1-3 句话复述需求核心]

## 功能点列表
| FP# | 描述 | 类型 | test_hints |
|-----|------|------|-----------|
| FP1 | ... | calculation | ... |
| FP2 | ... | workflow | ... |

## 约束条件
- C1: [约束描述] (关联: FP1)
- C2: [约束描述] (关联: FP2, FP3)

## 关联关系
- FP1 → FP2: [数据流描述]
- 不变量: [全局约束描述]

## 命中规则
- [规则名]: [匹配原因] (或 "无匹配")

## 澄清问题（如有）
- Q1: ...
- Q2: ...
```
